# Kindle Send for Mac Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native SwiftUI Mac app that searches Project Gutenberg and Standard Ebooks instantly from a local index, shows a cover grid, queues books and emails them to a Kindle over SMTP.

**Architecture:** All logic lives in a Swift package, `KindleSendKit` (catalog parsing, SQLite index and search, SMTP, sending, persistence), tested offline with `swift test`. A thin SwiftUI app target, generated by XcodeGen, depends on it. There are no third-party dependencies. SQLite comes from the system `SQLite3` module, and TLS/STARTTLS from `URLSessionStreamTask`.

**Tech Stack:** Swift 6.4 (Xcode 27), SwiftUI, Swift Testing (`import Testing`), system SQLite 3.54 (FTS5 + trigram), Security.framework Keychain, XcodeGen, FlowDeck for UI validation.

**Spec:** `docs/superpowers/specs/2026-10-20-mac-app-design.md`

## Global Constraints

- Minimum macOS **15.0**. Swift language mode 6 (strict concurrency).
- **Zero third-party packages** (system frameworks only).
- Passwords live **only** in the Keychain (service `com.by32.KindleSend`, account = SMTP user).
- No search query ever waits on the network. Every search runs against the local SQLite index.
- Catalog refresh: on launch if the index is older than **24 h**, and every 24 h while running. A failed refresh keeps the old index.
- HTTP User-Agent for every request: `KindleSend/1.0 (+https://github.com/by32/kindle-send)`. Standard Ebooks pages are fetched sequentially (one request at a time).
- Provider presets (host, port, per-email cap): Gmail `smtp.gmail.com` 465 25 MB · iCloud `smtp.mail.me.com` 587 STARTTLS 20 MB · Fastmail `smtp.fastmail.com` 465 50 MB · Yahoo `smtp.mail.yahoo.com` 465 25 MB · Custom: user-supplied host and port (465 = implicit TLS, 587 = STARTTLS), 50 MB.
- Per email: at most **25 attachments**, and the base64-encoded total must stay under the provider cap. 1 MB = 1,048,576 bytes.
- Gutenberg EPUB: `https://www.gutenberg.org/ebooks/{id}.epub3.images`, with fallback `…/ebooks/{id}.epub.noimages` when the encoded size exceeds the cap.
- Standard Ebooks EPUB: `https://standardebooks.org{path}/downloads/{path components after /ebooks/ joined by "_"}.epub?source=download` (verified: `/ebooks/mary-shelley/frankenstein` → `mary-shelley_frankenstein.epub`; also verified with a 3-component translator path).
- Gutenberg cover: `https://www.gutenberg.org/cache/epub/{id}/pg{id}.cover.medium.jpg`. Standard Ebooks cover: the `<img src>` inside each listing `<li>`, made absolute.
- App data dir: `~/Library/Application Support/KindleSend/` (`catalog.sqlite`, `queue.json`, `history.json`, `covers/`).
- Copy: the destination line reads `{kindle} · via {Provider name}`. The send button reads `Send {n} to Kindle`. The Amazon reminder reads: "Add {from} to Amazon's Approved Personal Document E-mail List, or Amazon will silently drop your books."

## Review Focus

1. **Catalog CSV quirks:** quoted fields with embedded newlines and commas, multi-language values (`en; fr`) and non-`Text` rows. The parser must handle all of them and skip non-text rows (Task 2 test `parsesQuotedMultilineAndSkipsNonText`).
2. **A queue send that half-fails** (one book's download 404s, or SMTP rejects batch 2 of 3): the books that did go out must be recorded as sent and leave the queue. The failed ones stay queued with a visible error, and nothing is sent twice on retry (Task 9 test `partialFailureKeepsOnlyFailedInQueue`).
3. **Odd search input:** an empty string, only punctuation, FTS operators typed literally (`AND`, `"`, `*`, `-`, `NEAR`) and one or two characters. None of these may throw or return SQL errors. Empty input shows the current chip's browse view (Task 5 test `hostileQueriesDoNotThrow`).
4. **A book larger than the cap even without images:** fail that book with "Too large to email (X MB > Y MB cap)" instead of sending a doomed email (Task 9 test `oversizeBookFailsClearly`).
5. **SMTP server error replies** (535 bad credentials, 552 message too large, a dropped connection mid-DATA): show an error that includes the server's reply text, and never hang (Task 7 test `authFailureSurfacesServerText`, and a 60 s read timeout in the transport).

### Task 5: Catalog database and search

**Files:**
- Create: `Catalog/CatalogDatabase.swift`, `Catalog/TypoTolerance.swift`
- Test: `CatalogDatabaseTests.swift`, `TypoToleranceTests.swift`

**Interfaces:**
- Consumes: `Work`, `Edition`, `Category`, `foldForSearch`
- Produces:
  ```swift
  public struct SearchQuery: Sendable, Equatable { public var text: String; public var category: Category; public var language: String? /* nil = all */; public var limit: Int = 120 }
  public final class CatalogDatabase: @unchecked Sendable {   // serial queue inside
      public init(url: URL?) throws                           // opens an existing DB; nil = in-memory
      public static func build(at url: URL?, works: [Work]) throws -> CatalogDatabase   // fresh DB (file or in-memory) in one transaction
      public func search(_ q: SearchQuery) throws -> [Work]
      public func work(id: String) throws -> Work?
      public var builtAt: Date? { get }                       // from meta table
  }
  public enum TypoTolerance { public static func trigrams(_ s: String) -> Set<String>; public static func similarity(_ a: String, _ b: String) -> Double /* Jaccard over trigrams */ }
  ```
  Schema:
  - `works(id TEXT PRIMARY KEY, json BLOB, popularity INTEGER, has_se INTEGER, languages TEXT, categories TEXT)`. `json` = encoded editions. `languages` and `categories` = `|en|fr|` style strings for `LIKE '%|en|%'` filtering.
  - `works_fts USING fts5(title, authors, subjects, content='', tokenize='unicode61 remove_diacritics 2')` with rowid = works rowid.
  - `works_tri USING fts5(title_authors, tokenize='trigram')`.
  - `meta(key, value)` holding `built_at`.

  Search algorithm:
  1. Folded text empty → browse: filter by category and language, `ORDER BY has_se DESC, popularity DESC LIMIT limit`.
  2. Else exact: each folded token becomes `"token"*` joined by spaces (implicit AND; quoting each token neutralizes FTS operators). Rank `bm25(works_fts, 10.0, 5.0, 1.0) - 2.0 * ln(1 + popularity) - 3.0 * has_se` ascending.
  3. If exact returns fewer than 5 rows and the folded text is at least 4 characters, run the typo fallback. Query `works_tri` with an OR of each query trigram (each quoted) and take 300 candidates. Re-rank in Swift by `TypoTolerance.similarity(query, title + " " + authors)`, then by popularity. Keep those with similarity ≥ 0.3. Append after the exact hits, without duplicates.

### Task 7: SMTP transport and client

**Files:**
- Create: `Delivery/SMTPTransport.swift`, `Delivery/SMTPClient.swift`, `Delivery/Providers.swift`
- Test: `SMTPClientTests.swift`

**Interfaces:**
- Produces:
  ```swift
  public enum SMTPSecurity: Sendable, Codable { case implicitTLS, startTLS }   // 465 → implicitTLS, else startTLS
  public struct SMTPAccount: Sendable, Codable, Equatable { public var host: String; public var port: Int; public var user: String; public var from: String; public var maxBytes: Int; public var security: SMTPSecurity { port == 465 ? .implicitTLS : .startTLS } }
  public enum Provider: String, CaseIterable, Codable, Sendable { case icloud, gmail, fastmail, yahoo, custom
      public var displayName: String; public var preset: (host: String, port: Int, maxBytes: Int)?; public var appPasswordHelpURL: URL? }
  public protocol SMTPTransport: Sendable {
      func connect(host: String, port: Int, tlsImmediately: Bool) async throws
      func startTLS() async throws
      func writeLine(_ s: String) async throws          // appends CRLF
      func write(_ data: Data) async throws
      func readReply() async throws -> (code: Int, text: String)   // handles multiline "250-…" replies; 60 s timeout
      func close() async
  }
  public final class StreamTaskSMTPTransport: SMTPTransport   // URLSessionStreamTask; startSecureConnection() for both modes
  public struct SMTPError: Error, LocalizedError { public var code: Int; public var serverText: String; public var stage: String }
  public struct SMTPClient: Sendable {
      public init(account: SMTPAccount, password: String, transport: @Sendable () -> SMTPTransport = { StreamTaskSMTPTransport() })
      public func verifyLogin() async throws                       // connect, EHLO, (STARTTLS, EHLO), AUTH, QUIT
      public func send(from: String, to: String, message: Data) async throws
  }
  ```
  Dialogue: expect 220 → `EHLO kindlesend.local` (250) → if startTLS: `STARTTLS` (220), `startTLS()`, `EHLO` again → `AUTH PLAIN base64("\0user\0pass")` (235) → `MAIL FROM:<from>` (250) → `RCPT TO:<to>` (250/251) → `DATA` (354) → dot-stuffed body + `\r\n.\r\n` (250) → `QUIT`. Any unexpected code throws `SMTPError` with the stage name and server text.

- [ ] **Step 1: Failing tests** with a `ScriptedTransport` (an ordered list of expected writes and canned replies, recording whether `startTLS()` was called):
  - `startTLSDialogueForPort587`: the iCloud account issues STARTTLS, then EHLO a second time, then AUTH, and `startTLS()` is called once.
  - `implicitTLSForPort465`: `connect(tlsImmediately: true)` and no STARTTLS command.

  ```swift
  public struct QueueItem: Codable, Hashable, Sendable, Identifiable { public var edition: Edition; public var addedAt: Date; public var lastError: String?; public var id: String { edition.id } }
  @MainActor @Observable public final class QueueStore { public init(fileURL: URL); public private(set) var items: [QueueItem]
      public func add(_ e: Edition); public func remove(id: String); public func contains(id: String) -> Bool; public func setError(_ msg: String?, for id: String) }   // persists on each change
  @MainActor @Observable public final class SendHistory { public init(fileURL: URL); public func wasSent(id: String) -> Bool; public func record(ids: [String], on date: Date) }
  public enum SendEvent: Sendable, Equatable { case downloading(id: String), sending(ids: [String], batch: Int, of: Int), sent(ids: [String]), failed(id: String, message: String), finished(sent: Int, failed: Int) }
  public protocol MailSending: Sendable { func send(from: String, to: String, message: Data) async throws }   // SMTPClient conforms
  public struct SendJob: Sendable {
      public init(downloader: EditionDownloader, mailer: MailSending, from: String, to: String, maxBytes: Int)
      public func run(_ editions: [Edition]) -> AsyncStream<SendEvent>
  }
  ```
  Behavior: download each edition sequentially, emitting `.downloading`. A download error emits `.failed` and the job continues. Batch the successful downloads, then send each batch. A batch success emits `.sent(ids)`. A batch failure emits `.failed` for each id in it, with the SMTP error text, and the job continues with the next batch. The job ends with `.finished`. The app layer (Task 12) maps `.sent` to `history.record` + `queue.remove`, and `.failed` to `queue.setError`.
